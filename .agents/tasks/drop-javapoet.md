## Goal

CoreJvm Compiler no longer uses or bundles JavaPoet, and no longer depends on
ToolBase's `classic-codegen`. Rejection throwables are generated with the Compiler's
Java type model, and the generated code stays the same.

## Context

- The Spine SDK is dropping the classic Java codegen libraries, JavaPoet and Roaster.
  Roaster went first (`drop-roaster.md`, PR #126). This branch is stacked on it.
- Only rejection-throwable generation used JavaPoet: `FieldType` and its
  implementations in `base`, and `RThrowableCode`, `RThrowableBuilderCode`, `Javadoc`,
  and `RThrowableRenderer` in `signal`.
- Generated rejections are API that users compile against, so the generated code is
  compared before and after the change.

## Plan

- [x] Capture the rejection throwables generated by `.103`: the `tests` build, the
      `signal` IgTest projects, and a probe project with more field kinds and name clashes
- [x] `base`: move `FieldType` and its implementations to the Compiler's `JavaTypeName`,
